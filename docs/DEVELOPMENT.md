# Разработка X-Manager Lite

## Назначение и границы

Lite получен из X-Manager `d97a3c50f51f729838376801d4e8fb9bb5edbea4`.
Это самостоятельный состав и канал Release, а не фильтр кнопок полного выпуска.
Полный репозиторий не изменён. Общие модели подписок сохранены ради совместимости
внешних ссылок; локальные службы OpenFlux/WebDAV/Volga/CottenDNS исключены.

| Требование | Основная реализация |
|---|---|
| Debian 12/13 amd64, root/systemd, блокировка установки | `scripts/installer-common.sh:xm_preflight` |
| Full и Lite не заменяют друг друга неявно | `scripts/lite-edition.py`, проверка манифеста в updater |
| Фиксированные компоненты собственного Release | `components.json`, `scripts/release-assets.py` |
| Резервирование, SQLite WAL, firewall, runtime sysctl, rollback | `scripts/installer-state.py`, `xm_begin/xm_exit/xm_finish` |
| Русская навигация | `bin/x-manager`, `scripts/menu-lite.sh`, `menu-v2.sh`, `menu-actions.tsv` |
| Одна активная реализация Snell | `snell-switch.py`, `snell6-endpoints.py`, `service-control.py` |
| Сохранение/синхронизация URI | `snell-subscriptions.py`, `mieru-subscriptions.py`, TUNA API |
| MasterDNS с сохранением локального resolver | `install-masterdns.sh`, `extract-masterdns.py` |
| Шлюзы независимого Xray или совместимой X-UI | `xray-discovery.py`, `xray_gateways.py`, `detect-gateways.py`, `plan-ports.py` |
| Ограниченный crash-restart / автосброс | `tuna-watchdog.py`, `tuna-recovery.py`, systemd timer |
| Локальные health-пробы | `watchdog-health.py`, `tuna-healthcheck.timer` |
| Адаптивная сеть / отдельные TCP-настройки | `network-profile.py`, `tcp-profile.py` |
| Запланированная перезагрузка | `reboot-schedule.py` |

Все эти пути относительны корню репозитория. Установленная полная копия находится
в `/usr/local/share/x-manager/distribution`; её надо обновлять вместе с меню и
хелперами. Смешивание файлов разных выпусков не поддерживается.

## Установка и обновление

1. Проверить платформу, root/systemd, FD-блокировку, редакцию установки.
2. Проверить зависимости, сохранённые настройки, сторонние слушатели и порты.
3. Скачать выбранные компоненты во временный каталог и проверить SHA-256.
4. Создать закрытую копию; SQLite сохранять через backup API, включая WAL.
5. Приостановить известные конфликтующие средства восстановления на обслуживание.
6. Применить изменения; существующие ключи, UUID, токены, порты и режимы сохранять.
7. Проверить конфигурацию и реальный старт требуемых служб. Ручной stop/off сохранять.
8. Восстановить исходное состояние внешнего watchdog. При ошибке — rollback.

При миграции схемы требуется отдельная проверка сохранения уже существующих
пользователей и URI. Не менять кодеки/режимы для прохождения теста. Не выдавать
успех после неуспешного curl, валидации либо systemctl. APT не является частью
файлового rollback; это явно описано пользователю.

Пакеты Snell v5/Mieru обновляются основным установщиком. MasterDNS обновляется
там же, если уже настроен. Создание и обновление ядра endpoint Snell v6 — через
его транзакционный помощник. Для новой версии v6 согласованно менять VERSION,
CORE_SHA256, ARCHIVE_SHA256 и манифест; затем проверять реальное переключение.
Ядра qWDTT/CSQTT/Xray принадлежат существующей установке и не заменяются Lite.

## Подписки и совместимость клиента

TUNA сохраняет исходные таблицы и внешние схемы, включая дополнительные URI,
контейнеры групп и каталоги для совместимости. Отсутствие локальных менеджеров
OpenFlux/WebDAV не требует удаления этих полей из пользовательских данных.
Управляющий API и HTTP слушают localhost. Внешний агрегатор не переписывается.

Изменение URI выполняйте по явной привязке к локальному подключению; одинаковое
название не является идентификатором. Внешний URI нельзя подменять локальным.
Обновление группы должно учитывать ревизию, источник маршрутизации, уникальность
участников и семейство. TUI не должен терять введённые поля при ошибке.
В терминальном меню — читаемый результат; JSON оставлять для машинного CLI/API.

## Watchdog

`service-control.py` — источник намерений stop/off/autostart. Его проверки
обязательны перед любым восстановлением. Новая политика systemd: burst=6
(первый старт + 5 повторов), pause=5, для Xray/X-UI pause=30. Интервал systemd
бесконечный, но управляемый recovery-таймер снимает блокировку после 300 секунд.
Только точная управляемая политика допускается к автоматическому сбросу.
Чужие drop-in, маски, остановленные и невыбранные Snell не обходить.

Счётчик crash-recovery и счётчик локальных health-проверок различаются.
Health-проверка работающего процесса не доказывает доступность внешнего транспорта.
Лимит OpenFlux и его файлы отсутствуют в Lite.

## Тестирование

На Linux нужны bash, Python 3.11+, jq, openssl и закреплённый `mita` в PATH:

```bash
python3 -m unittest discover -s tests
python3 -m unittest discover -s tuna-sub-server/tests
```

Не запускайте весь набор от root на рабочем VPS: часть тестов предназначена
для изолированной ОС и вызывает настоящий установщик с подменёнными зависимостями.
Для интеграции используйте отдельную VM со snapshot и маркером
`/.x-manager-test-lab`. Это ограничитель случайного запуска, не sandbox.

```bash
XM_COMPONENT_DIR=/opt/assets bash install.sh --direct
XM_COMPONENT_DIR=/opt/assets python3 tests/acceptance_vm.py
python3 tests/watchdog_vm.py
```

`acceptance_vm.py` создаёт синтетического пользователя, меняет тестовые службы,
проверяет повторный запуск, неудачную загрузку, отказ службы/rollback,
TCP-профиль, MasterDNS, Snell v5/v6 и публикацию. Повторный прогон выполняйте
из свежего snapshot VM. `watchdog_vm.py` создаёт искусственную `csqtt.service`
только если реальной службы нет, проверяет реальные systemd-попытки и 300 секунд
ожидания; это проверка механизма восстановления, а не протокола CSQTT.

Для обновления обязательно сохранить снимок users/токенов/URI и конфигураций,
проверить off/stopped, затем сравнить после обновления и после намеренного отказа.
Для релиза отдельно прогоняйте bootstrap/update из опубликованных assets.
Физическое устройство, VPS, DNS-делегирование, панели и долгий прогон — отдельные
уровни проверки. Их нельзя заменять результатом unittest.

## Выпуск

Единственный канал Lite — `lesovoi53/x-manager-lite`. Изменить `components.json`
и зафиксированный bootstrap-тег в `install.sh`, проверить выбранные assets,
лицензии/соответствующие исходники, затем собрать архив из чистого checkout:

```bash
python3 scripts/build-release.py --assets /path/to/verified-assets --output /path/to/release
```

Архивы исходников Mieru и Snell v6 идут в том же Release. Публикуются
`x-manager.tar.gz`, `quick-start.sh`, `SHA256SUMS` и все assets манифеста.
Сначала создать draft, загрузить полный комплект, проверить хеши, затем
опубликовать обычный Release как latest. Простого push в main недостаточно
для обновления из меню. Локальные журналы, базы, конфиги и пароли не публиковать.
