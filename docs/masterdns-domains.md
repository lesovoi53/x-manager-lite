# Несколько доменов MasterDnsVPN

Одна служба `masterdns.service` обслуживает массив `DOMAIN` из 1–16 DNS-имён.
Откройте MasterDnsVPN → «Домены этого сервера» (также доступно в параметрах
подключения). Добавление, удаление и выбор первого домена меняют только черновик.
`0` или конец ввода отменяет черновик. Последний домен удалить нельзя.

Сохранение проверяет TOML и отсутствие внешних изменений, сохраняет остальные
настройки, права и владельца конфигурации. Работающая разрешённая служба
перезапускается; выключенная или остановленная остаётся остановленной. Автозапуск,
маски systemd и ограничения service-control не меняются. Если запись или
перезапуск не удались, восстанавливаются прежний файл и активное состояние;
ошибка восстановления явно сообщается. Проверка старта занимает четыре секунды
и не заменяет длительную проверку подключения клиента.

При экспорте выбирается формат: **StormDNS** создаёт отдельную `stormdns://`
ссылку для каждого домена; **TUNA** создаёт одну `tuna://` ссылку с полным списком
доменов в одном профиле. Это одна серверная конфигурация, не группа разных VPS.
Уже выданные подписки и база пользователей автоматически не обновляются. Ключи,
имена профилей и маршрутизация при работе с доменами сохраняются. Префикс `d.`
не добавляется. Настройки выбранного профиля одинаковы в обоих форматах.

TUNA использует существующий клиентский формат `ProfileEncoder`: JSON UTF-8,
zlib с максимальным сжатием, Base64URL без padding. JSON содержит один объект
`{"name": ..., "uri": ...}`; внутренний URI хранит весь массив `profile.domains`
и первый домен в `profile.server.domain`. Клиент назначает импортируемому профилю
новый ID. Самописной контрольной суммы нет: используется Adler32 потока zlib.
Генератор соблюдает ограничения клиента: внутренний MasterDNS JSON до 65536 байт,
URI до 100000 символов, внешний JSON до 4 MiB и ссылка для передачи до 128 KiB.

Для новых ссылок все три экспортируемых профиля используют значения по умолчанию:
`resolver_balancing_strategy=5` (Hybrid Score: приоритет потерь с учётом задержки),
`upload_compression_type=2`, `download_compression_type=2` (LZ4 в обе стороны),
`rx_tx_workers=16`, `tunnel_process_workers=0`. Остальные различия трёх профилей,
явно выбранное имя, ключ и список доменов сохраняются. Эта настройка генератора
не переписывает уже выданные ссылки, подписки или параметры сохранённых клиентов.
Значения 2 и 5 сверены с нативными `internal/compression/types.go` и
`internal/client/balancer.go` MasterDnsVPN, а также `client_config.toml.simple`.

## Параметры экспортируемых ссылок

«Параметры подключения» → `[6] Параметры экспортируемых ссылок` позволяет выбрать
один из трёх профилей и настроить резолверы, балансировку и дублирование, сжатие,
рабочие потоки, MTU, ARQ, интервалы ping и прочие параметры клиента. Просмотр и
сброс меняют только черновик; изменения применяются отдельным «Сохранить».
Выход отменяет черновик. Настройки остальных профилей сохраняются.

Файл `client_link_profiles.json` рядом с серверным TOML создаётся только при
явном сохранении, с правами `0600`. Если файла нет, используются значения по
умолчанию. Повреждённый файл блокирует экспорт вместо скрытого сброса настроек.
Запись атомарная, с блокировкой и проверкой внешних изменений. Это параметры
новых ссылок; сохранение не перезапускает службу, не меняет ключ, домены, метод
шифрования, пользователей или ранее выданные подписки.

## Метод шифрования

«Параметры подключения» → `[5] Метод шифрования` показывает текущий метод и шесть
вариантов нативного ядра: `0 NONE` (без шифрования), `1 XOR`, `2 ChaCha20`,
`3 AES-128-GCM`, `4 AES-192-GCM`, `5 AES-256-GCM`. `Enter` отменяет выбор.
Один метод действует для всей службы и всех её доменов. После изменения клиентам
нужны соответствующие параметры; новые ссылки содержат фактически выбранный
`profile.server.encryption_method`. Существующие подписки не перезаписываются.

Ядро требует 16 байт текста ключа для AES-128-GCM, 24 для AES-192-GCM и 32 для
остальных методов. Это длина текстового ключа, а не декодированных hex-байтов.
Совместимый ключ сохраняется. При несовместимости меню предлагает **явно**
создать новый случайный ключ, затем отдельно подтвердить применение. Отказ
сохраняет прежние ключ и метод. Новое значение ключа не выводится в этом меню;
оно доступно в явно запрошенном экспорте профиля.

Метод и при необходимости ключ сохраняются одной операцией под блокировкой
жизненного цикла. Перед заменой ключа активная служба временно останавливается,
чтобы её автоматический перезапуск не встретил несовместимую пару ключ/метод.
При сбое записи или запуска восстанавливаются оба файла и прежнее активное
состояние. Права файлов сохраняются. Изначально остановленная служба не
запускается. Установка кода меню сама по себе не меняет метод или ключ.
Обычное меню смены ключа также учитывает требуемую длину выбранного метода и
использует ту же операцию с восстановлением файлов при ошибке; ошибки генерации
и запуска не скрываются.

Проверка DNS информационная: запрашивает делегирование у NS родительской
авторитетной зоны. Отсутствие ответа от самой туннельной зоны не считается
ошибкой делегирования. При отсутствии `dig` ничего не устанавливается.
Один DNS-запрос ограничен тремя секундами, вся проверка — 45 секундами.
Наличие NS не подтверждает адреса NS, доступность UDP/53 или клиентское соединение.

## Установщик

`bash scripts/install-masterdns.sh` обновляет существующую установку, сохраняя
массив доменов. Для новой установки домены обязательны:

```sh
bash scripts/install-masterdns.sh d.example.org d1.example.org
```

Позиционные аргументы — явный запрос заменить полный список (1–16 имён).
Одиночный аргумент совместим с прежним CLI и явно задаёт один домен. Для обновления
существующего сервера без изменения списка используйте вызов без аргументов;
меню повторной установки использует именно его. Основной `install.sh` также
сохраняет существующую конфигурацию. Новые настройки не разворачивают отдельные
службы и не затрагивают подписки.

## Проверки

```sh
python3 -m unittest discover -s tests -p 'test_masterdns*.py' -v
python3 -m unittest discover -s tests -v
for script in bin/x-manager scripts/install-masterdns.sh install.sh; do bash -n "$script" || exit 1; done
```

Тесты используют временные файлы и подставной контроллер systemd. Linux-тест
экспорта выполняет настоящие функции Bash и проверяет профили с 1, 2, 4 и 7
доменами в обоих форматах, включая сохранённые пользовательские параметры.
