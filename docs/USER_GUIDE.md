# Руководство X-Manager Lite

## Установка

Debian 12/13, x86_64, root, работающий systemd. ARM64, Ubuntu и контейнер без
systemd не поддержаны. APT-зависимости: curl, wget, jq, unzip, iptables, qrencode,
openssl, python3, iproute2, ca-certificates, kmod. Системные пакеты берутся из
настроенных репозиториев Debian, прикладные бинарники — из собственного Release
Lite с проверкой хешей.

Из распакованного полного выпуска:

```bash
bash install.sh --quick     # существующее совместимое ядро Xray
bash install.sh --direct    # прямой выход Snell/Mieru без Xray
bash install.sh --manual    # интерактивный выбор
bash install.sh --update    # сохранить действующие настройки и состояния
```

ОС, архитектура, порты и компоненты проверяются до замены рабочих файлов.
Ошибка скачивания, хеша, конфигурации или запуска прерывает операцию.
После начала замены выполняется восстановление из копии. Ошибка самого
восстановления также выводится явно. Пакеты APT и созданные системные учётные
записи откатом не удаляются.

443/8443 не выделяются новым слушателям. Занятый стандартный порт заменяется
свободным разрешённым. Сохранённые порты автоматически не меняются;
некорректная сохранённая конфигурация требует исправления.

## Snell

Главная → Snell → v5 или v6. Активация v6 останавливает v5, и наоборот.
Переключение сохраняет ключи и конфигурации, проверяет авторизованное
соединение и восстанавливает прежнее состояние при ошибке.

v5: имя, общий PSK, порт, HTTP-обфускация, Direct/Xray, firewall, ссылка и QR.
Версия протокола в URI зависит от совместимого режима и не обязана совпадать
с номером пакета серверного бинарника.

v6: имя, порт, общий PSK, адрес сервера в ссылке, адрес прослушивания, маршрут,
firewall, режимы `default`, `unshaped`, `unsafe-raw`, адрес проверки готовности.
Свойства защиты режимов различаются; переход выбирается явно, установщик их
не подменяет. Отдельный QUIC Proxy не создаётся. Проверка «Snell → HTTPS»
подтверждает TCP с авторизацией, не подтверждает UDP клиента.

Локальные ссылки в подписке публикуются только для выбранной активной версии.
Привязанные ссылки обновляются при изменении локального подключения;
внешние сохраняются. Раздел подписки пользователя управляет ссылками
и не открывает серверные настройки. Обновление закреплённого ядра v6 находится
в его настройках; переход между версиями сервера всегда явный.

## Mieru

Подключения, настройки и обслуживание: пользователи/пароли, имя, TCP/UDP-порты,
обфускация и traffic pattern, Direct/SOCKS5, firewall, журнал, restart, URI/QR.
Генератор использует закреплённый родной кодек `mita`; traffic-pattern
кодируется в URL один раз. Синхронизация учитывает сохранённые привязки
и ревизии. Импорт в конкретную версию приложения проверяется отдельно.

## MasterDnsVPN

Главная → MasterDNS → установка. Требуется своя DNS-зона и делегирование
на сервер; записи у DNS-провайдера Lite не создаёт. Без домена служба не создаётся.
При свободном UDP/53 используется `0.0.0.0`. Если локальный resolver занимает
loopback, проверяется отдельный IPv4-адрес исходящего интерфейса. Конфликт на
адресе сервера останавливает установку; системный DNS не отключается.
За NAT нужно перенаправление UDP/53. После смены адреса проверьте `UDP_HOST`.

Новый туннель наследует маршрут Snell: Direct либо SOCKS5 Xray.
Сохранённые конфигурация и ключ не генерируются заново при обновлении.
Повторная настройка с другим доменом меняет DOMAIN и обновляет ядро/службу.
Обновление Lite также обновляет уже установленное ядро MasterDNS.

## qWDTT и CSQTT

Обслуживаются существующие `wdtt.service` и `csqtt.service` с известными
путями и конфигурациями. Lite не скачивает их установщики и не заменяет ядра.
qWDTT: устройства/трафик, имя, URI, Direct/Xray, firewall, логи и restart.
CSQTT: доступ к VPN, закрытие панели за SSH-туннелем, реквизиты, имя, URI,
учётные данные и журналы. Маршрутизацией CSQTT управляет сама.
Неизвестная форма ExecStart или неоднозначный порт блокирует автоопределение.

## Подписки

HTTP по умолчанию только на `127.0.0.1:22217`. Внешний агрегатор забирает его
локально. Публичный HTTP/TLS-прокси не создаётся. UUID, токен, ревизии и SQLite
сохраняются при обновлении. Доступны создание из служб или вручную, внешние URI,
редактирование списков, отключение публикации, отзыв токена и удаление.

Форматы: `/sub/<token>` — ссылки в Base64; `/sub-json/<token>` — JSON групп;
`/sub-groups/<token>` — контейнер групп для согласованного клиента/агрегатора.
Токен секретный. Выдача URI не означает, что клиент поддерживает этот протокол.

URL-test/Speedtest: тип, семейство, участники, порядок, стратегия результата,
URL, GET/HEAD, допуск, периодический тест, интервал, тест при подключении,
таймаут/HTTP-статус, удержание, подтверждения, срок годности результата,
запросы на узел, профиль-источник, мобильная сеть. Для Speedtest — длительность
и бюджет трафика. Предлагаются готовые URL и явный выбор собственного URL.
Измеряет клиент после подключения, сервер сохраняет настройки.

`0` в форме запускает проверку и затем подтверждение сохранения. Если не хватает
участников или источника, причина остаётся до Enter. `99` отменяет изменения.
Минимум участников — два. Раздел дополнительных узлов принимает внешние URI.

## Watchdog

Главная → Watchdog. Аварийный перезапуск выполняет systemd. Базовые значения:

| Службы | Повторных попыток | Пауза |
|---|---:|---:|
| TUNA, выбранный Snell, Mieru, MasterDNS, qWDTT, CSQTT | 5 | 5 с |
| Xray / X-UI | 5 | 30 с |

После исчерпания — 300 секунд ожидания и новый цикл через `tuna-recovery.timer`.
Фактический запуск: 300 секунд плюс ожидание очередного тика. Systemd также
считает ручные старты; отображаемый остаток — верхняя оценка автоповторов.
Пользовательские политики не заменяются базовыми автоматически.

Для работающих, но зависших процессов есть `tuna-healthcheck.timer`: локальные
TCP/HTTP/SOCKS-пробы и поиск процесса Xray в cgroup X-UI. Их настройки/счётчики
показаны отдельно. Это не измерение интернета каждого клиента. Внешний watchdog
не требуется. При конфликте он показан явно; во время обновления известный
внешний watchdog временно приостанавливается и возвращается в прежнее состояние.

Обычный stop действует до явного запуска или перезагрузки. «Выключить постоянно»
сохраняется после обновления/перезагрузки. Пустые слоты Snell скрыты, невыбранная
версия не запускается автоматически.

## Оптимизация

На чистой установке адаптивный профиль применяется с резервной копией.
Учитывается физическая RAM и лимит cgroup, но не swap:

| Эффективная RAM | rmem_max / wmem_max | conntrack_max |
|---|---:|---:|
| <1 GiB | 4 MiB | 65 536 |
| 1–<2 GiB | 8 MiB | 131 072 |
| 2–<4 GiB | 16 MiB | 262 144 |
| ≥4 GiB | 16 MiB | 524 288 |

Большие существующие лимиты сохраняются. Также задаются BBR/fq, backlogs,
TCP keepalive/fin и отдельные таймауты conntrack; точные значения видны в плане.
Конфликтующие пользовательские sysctl-файлы блокируют применение. Повторная
установка не пересчитывает сохранённый профиль. `rp_filter`, маршруты и текущие
qdisc интерфейсов этим профилем не меняются.

Дополнительные параметры выбираются отдельно: [8] → [3].

- `tcp_notsent_lowat=16384`: порог непереданных TCP-данных/готовности записи,
  **не ограничение всех сетевых буферов до 16 KiB**.
- `tcp_slow_start_after_idle=0`: отключить уменьшение окна после простоя.
- `tcp_fastopen`: добавить биты client/server, сохранить остальные биты.
  Приложение также должно поддерживать и использовать TFO.

Есть просмотр, применение и откат. Чужое изменение файла/значения блокирует
разрушительный откат. Ускорение не гарантируется; это не настройка UDP.
Семантика: [документация ядра Linux](https://docs.kernel.org/networking/ip-sysctl.html).

Ежедневная перезагрузка выключена по умолчанию; включается в обслуживании
с указанием времени. Она прерывает соединения и блокируется на время установки.

## Резервные копии

Данные: `/etc/x-manager`, `/etc/snell`, `/etc/snell6`, `/etc/mita`, `/etc/masterdns`,
`/etc/tuna-subscriptions`, `/var/lib/tuna-subscriptions`. Скрипты:
`/usr/local/share/x-manager`; сохранённый установщик — его каталог `distribution`.

```bash
bash /usr/local/share/x-manager/distribution/install.sh --backup
bash /usr/local/share/x-manager/distribution/install.sh --rollback /var/backups/x-manager-XXXXXXXX
```

Укажите существующий путь из вывода установщика. Копии Full не принимаются.
Восстанавливаются управляемые файлы, SQLite через backup API, firewall,
сетевые параметры и исходные состояния служб. Откат возвращает старые данные,
поэтому текущее состояние сначала резервируется. Копии закрыты `0700`, содержат
секреты и не предназначены для публикации. После отката проверьте службы.
